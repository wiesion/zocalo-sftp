# 10 - Security Boundary

Adversarial test suite. The other examples show that things *work*; this one
tries to make them fail open. It has no interactive `setup.sh`: everything,
including `config/`, is generated by `test.sh` and removed afterwards.

| Group | What is attacked | Expected |
|-------|------------------|----------|
| A | Hostile config: duplicate UID/username/project/GID, project GID equal to `SFTP_USERS_GID`, reserved names, malformed members, world-accessible `SFTP_PROJECT_MODE` | Container exits non-zero with a specific message, `/etc/passwd` untouched |
| B | Authenticated non-member: list, stat, get, put, rm, mkdir, rename (in and out), symlink, hardlink, chmod, `../` and absolute paths, shell command | Every operation denied; project data intact |
| C | Drifted project directory (wrong owner/group/mode), planted symlink, missing directory | Repaired to `root:GID 2770` without following the symlink |
| D | Project removal, GID reuse, user disable/enable | Removal revokes access; reused GID does not unlock old data |
| E | Invalid config pushed at runtime (duplicate GID plus a valid new user); removing a user still listed in a project | Invalid config: nothing applied, rejection logged, no one locked out. Removal: user locked, stale reference dropped |
| F | Restart | Reconciled state is retained |

Project storage is a named volume rather than a bind mount so that POSIX group
permissions are enforced on every host (Docker Desktop bind mounts are not).

```bash
./test.sh
```
